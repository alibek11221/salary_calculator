# Дизайн: система отпусков

Дата: 2026-07-12. Статус: утверждён.

## Цель

Два сценария:
1. Отчёт за месяц (`GET /api/v1/salary/report`) корректно учитывает отпуск: меньше отработанных дней, меньше еды, плюс отпускные по среднему заработку.
2. Прикидка «сколько получу отпускных» по датам будущего отпуска — без сохранения.

Вне скоупа: учёт остатка дней отпуска (баланс 28 дней/год), перенос выплаты отпускных в предыдущий месяц по правилу «за 3 рабочих дня».

## Данные

Миграция `create_vacations_table`:

```sql
CREATE TABLE IF NOT EXISTS vacations
(
    id        UUID NOT NULL PRIMARY KEY DEFAULT uuid_generate_v4(),
    date_from DATE NOT NULL,
    date_to   DATE NOT NULL,
    CHECK (date_to >= date_from)
);
```

- Полноценные `DATE` (а не `VARCHAR "YYYY_MM"` как у бонусов): отпуск живёт внутри месяца и может пересекать его границу.
- В API даты в ISO-формате `2006-01-02`.
- Пересекающиеся периоды запрещены: при add/edit usecase проверяет пересечение (SQL-запросом по диапазону) и возвращает `ErrOverlappingVacation`.
- `date_from > date_to` и годы до `StartYear` (2024) — ошибка валидации DTO.

Запросы `queries/vacations.sql`: `ListVacations`, `GetVacationsInRange` (пересечение периода с диапазоном дат), `InsertVacation`, `UpdateVacation`, `DeleteVacation`.

## Средний заработок и отпускные

Новый сервис `internal/services/vacation_pay` (интерфейсы потребителя в `contract.go`, mockgen — по паттерну репозитория).

- Расчётный период: 12 календарных месяцев `[M-12 … M-1]`, где M — месяц начала отпуска.
- Доход месяца m = оклад, действующий в m (последний `salary_changes.change_from <= m`) + сумма премий (`bonuses`) за m. Дежурства и еда в средний не входят.
- Если для ранних месяцев оклада ещё нет (история короче 12 мес) — такие месяцы выпадают из суммы **и из делителя**: `средний дневной = Σ доходов / N месяцев с данными / 29.3`. Если данных нет совсем — ошибка.
- Оплачиваемые дни отпуска = календарные дни периода **минус госпраздники** (`type_id = 3` в календаре, ст. 120 ТК). Выходные (type 2) входят и оплачиваются.
- `отпускные gross = средний дневной × оплачиваемые дни`; net = gross минус НДФЛ по ставке `sCtx.CurrentNDFL()` (та же, что для оклада).

## Влияние на отчёт месяца

В `get_salary_report` / `calculator`:

- Из БД берутся отпуска, пересекающиеся с отчётным месяцем (`GetVacationsInRange`).
- Дни пересечения отпуска с месяцем, попавшие на **рабочие** дни (type 1 и 5): числа 1–15 вычитаются из `FirstHalfDays`, 16+ — из `SecondHalfDays`. `TotalWorkdays` месяца не меняется (знаменатель формулы остаётся полным).
- Еда: `529 × (TotalWorkdays − отпускные рабочие дни месяца)`.
- Отпускные добавляются в `extra_payments` строкой `{name: "Отпускные", type: "extra"}` — **net-сумма**, вся целиком в месяце **начала** отпуска. В месяце-хвосте (если отпуск пересёк границу) — только вычет дней, без выплаты.
- Несколько отпусков в месяце допустимы: вычеты и выплаты суммируются, каждая выплата отдельной строкой.

## API

Роут-регистрар `routes/vacation.go`, `Name() = "vacations"` → `/api/v1/vacations`:

| Метод | Путь | Что |
|---|---|---|
| GET | `/` | список отпусков |
| POST | `/` | добавить `{"from": "2026-08-03", "to": "2026-08-16"}` |
| PUT | `/` | изменить `{"id", "from", "to"}` |
| DELETE | `/` | удалить `{"id"}` |
| GET | `/estimate?from=&to=` | прикидка без сохранения |

Ответ estimate:

```json
{
  "avg_daily": 11890.45,
  "paid_days": 14,
  "gross": 166466.3,
  "net": 144825.68,
  "affected_months": [
    {"month": "2026_08", "advance": 100000.0, "salary": 90000.0, "total": 190000.0}
  ]
}
```

`affected_months` — отчёт затронутых месяцев, пересчитанный с гипотетическим отпуском (реюз логики отчёта). Уже сохранённые отпуска этих месяцев тоже учитываются.

## Структура кода

По принятому паттерну «пакет на действие»:

- `internal/dto/{add_vacation, edit_vacation, delete_vacation, list_vacations, estimate_vacation}`
- `internal/usecase/vacations/{add, edit, delete, list, estimate}` — contract.go + usecase.go + тесты + mockgen
- `internal/http/handlers/{add_vacation, edit_vacation, delete_vacation, list_vacations, estimate_vacation}` — swagger-аннотации
- `internal/http/routes/vacation.go`
- `internal/services/vacation_pay` — средний заработок, оплачиваемые дни, сумма отпускных
- `calculator`: новая зависимость (vacation_pay + repo-метод) для строки «Отпускные» и вычета дней

После изменения SQL — `make sqlc-gen`; контрактов — `make mocks`; хендлеров — `make swagger`.

## Ошибки

- Пересечение периодов → `ErrOverlappingVacation` (409)
- `from > to`, кривой формат дат, год < 2024 → 400
- Нет ни одного месяца с окладом для среднего → 500 с внятным сообщением
- Нет календаря на год отпуска (нет `workdays_YYYY.json`) → та же ошибка, что сейчас у отчёта

## Тесты

- `vacation_pay`: средний при смене оклада внутри 12 мес; с премиями; неполная история (<12 мес); отсутствие данных; праздники внутри периода уменьшают оплачиваемые дни.
- Вычет дней: отпуск целиком в первой половине / во второй / через обе; через выходные; через границу месяца (в каждом месяце свой вычет); несколько отпусков в месяце.
- Отчёт месяца с отпуском: строка «Отпускные» в месяце начала, отсутствие строки в месяце-хвосте, еда уменьшена.
- Estimate: суммы и `affected_months`, учёт уже сохранённых отпусков.
